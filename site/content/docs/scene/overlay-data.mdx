---
title: Overlay data and guides
description: Add labels, measurements, declared data sources, and explicit interactions to a scene.
---

MolGFX exposes scene items beyond molecular representations. Use them when the item has a clear semantic owner in your application; MolGFX does not detect interactions or load volume and trajectory files for you.

## Labels and measurements

Anchors can be in world coordinates or target a selection. Labels and measurements are scene items:

```python
first = molgfx.annotation.world((0.0, 0.0, 0.0))
second = molgfx.annotation.world((4.2, 0.0, 0.0))

scene.add(molgfx.annotation.label(anchor=first, text="site"))
scene.add(molgfx.measurement.distance(first, second))
```

`measurement.angle` takes three anchors; `measurement.dihedral` takes four. Selection anchors use `molgfx.annotation.selection(structure=scene.structure_id, target="resname HEM")`.

## Explicit overlay interactions

Author an interaction only when your application or upstream analysis supplies it:

```python
scene.add(molgfx.interaction.explicit(
    kind="hydrogen_bond",
    first=first,
    second=second,
))
```

The public interaction kinds are `hydrogen_bond`, `salt_bridge`, `pi_stacking`, `cation_pi`, `hydrophobic`, `metal_coordination`, and `contact`. MolGFX does not expose interaction detection; use MolFrame or another analysis step to establish the overlay result first.

## Volumes, properties, and trajectories

`molgfx.data.source()` declares the identity and optional location/format of an external overlay data source. It does not upload the payload. The portable scene specification intentionally carries descriptors rather than bulk volume or trajectory values.


For scalar coloring, bind values to a structure with `scene.bind_property(...)`, then pass the returned property to `molgfx.color.property(...)`. Trajectory declarations use `molgfx.trajectory.bind(...)`; their frames must match the declared structure topology and source identity before a renderer can resolve them.

<Callout type="info" title="Keep raw data outside the scene document">
Use stable source hashes and let the application or binding provide the payload. This keeps scene JSON portable and makes failure to resolve a overlay source explicit instead of silently visualizing a different dataset.
</Callout>
